# 第 0 轮：最小闭环（数形版，拍照输入）

照着 TuSou 评测计划的第 0 轮改写。**目标**：完整走一遍「测量 → 找出失败 → 猜原因 → 验证 → 改进 → 再测量」，**不写评测代码，全部手动完成**，大约 2～3 小时，最好一次坐下来做完。

这一轮比较的是 **2B 和 4B**，输入方式是**拍照**（这是数形最主要的用法）。同一张照片，两个模型各自“识别 + 作图”一次。它回答的问题是：**手机上用 2B 够不够？不够的话，差在识别还是作图、差在哪类题？**

另外，到目前为止的评测用的都是程序生成的清晰图片，**真实照片还没有测过**。这一轮也补上这一点。

## 分工

| 步骤 | 谁做 |
|---|---|
| 1. 挑题、拍照 | **你** |
| 2. 运行之前写好「正确的图应该显示什么」和答案 | **你**（这一步最重要，不能让 Claude 代写） |
| 3. 两个模型各跑一遍，填表 | 你操作、判断对错；Claude 负责开关 Ollama 和网页 |
| 4. 挑 3 个失败，写下猜测 | **你** |
| 5. 不改代码，验证猜测 | 你设计、操作；Claude 可以帮你看作图命令 |
| 6. 做一个小改进，再测一次 | 你决定改什么，Claude 写代码（日志里如实写明） |

## 基本原则（和 TuSou 一样）

1. **先写答案，再运行。** 每道题「正确的图应该显示什么」必须在运行之前写好。看了结果再定标准，就是在给自己放水。
2. **一次只改一样东西。** 改完用同样的照片再测，才知道变化是哪个改动带来的。
3. **结果如实记录，失败也记。** 「这个改进没用」同样是结论。
4. **猜测先写下来，再去验证。** 「我觉得是因为……」写在前面，再设计实验证明或推翻它。

## 步骤 1：挑 12 道题、拍照（约 30 分钟）

从课本、练习册、试卷里挑，**刻意挑你觉得难画的**。分 3 类，每类 4 道，例如：

| 类型 | 例子（只是举例，请换成你自己的题） |
|---|---|
| 函数 | 含参数的二次函数、三角函数、分段函数、函数与直线的交点 |
| 积分 | 曲线与 x 轴围成的面积、两条曲线所围的面积、定积分的值 |
| 几何 | 三角形里的中点和垂线、圆和切线、四边形、正方体或棱锥 |

分类可以按你的兴趣换，但每类保持 4 道，最后的对比表才好看。

拍照：

- 用手机相机拍，**每张只拍一道题**（一页上有几道题时，拍完在相册里裁一下，或者拍近一点）。
- 光线正常、尽量正对纸面，像平时真的要用这个 App 时那样拍就行，**不用刻意拍得特别好**。
- 用隔空投送传到 Mac，告诉 Claude 放在哪里，它会把照片放进 `eval/round0/photos/`，改名为 `p01.jpg` 到 `p12.jpg`。照片不会进 git（已加进 `.gitignore`）。

## 步骤 2：运行之前写好标准（约 30 分钟）

在 `problems.csv` 里，每道题一行：

```csv
id,type,photo,figure_must_show,answer,note
p01,函数,p01.jpg,抛物线开口向上；与 x 轴交于 (-1,0)、(3,0)；顶点 (1,-4),交点 (-1,0)、(3,0)；顶点 (1,-4),只要这三个点位置对就算对，不要求标注文字
```

（上面这一行只是格式示例，不要照抄进表里。）

- `figure_must_show`：正确的图**必须**有哪些东西，写成能一眼核对的要点，比如「AB = 5」「DE ⊥ AC」「顶点 (1, -4)」「阴影在 x = 0 到 2 之间」。
- `answer`：这道题的正确答案（用来检查“解题思路”，可选）。
- `note`：遇到「这样画算不算对」时，把你的判断理由写在这里。你会发现，**定标准本身就需要做决定**。
- 题目原文**不用打字**：识别得对不对，跑的时候对着照片看就行。

题目里用中文逗号「，」没关系；如果某一格里有英文逗号「,」，把这一整格用英文双引号括起来。也可以用 Numbers 或 Excel 打开这个文件填写。

## 步骤 3：两个模型各跑一遍，填表（约 60 分钟）

告诉 Claude「开始第 0 轮第 3 步」，它会启动 Ollama 和网页版（`npm start`）。在网页里：

1. 右上角切换模型：`qwen3.5:2b-q4_K_M` 或 `qwen3.5:4b-q4_K_M`（这个模型同时负责识别和作图，和手机上一样）；
2. 「拍照 / 图片」→「选择图片」→ 选 `photos/p01.jpg` →「识别并可视化」；
3. 同一张照片两个模型各跑一次。

为什么在电脑上跑：两个模型都有、每次只要几秒到十几秒，同一张照片能公平比较。注意：电脑上用 Ollama 运行模型，手机上用 llama.cpp，模型相同，但图片缩小的方式可能不一样（手机上最多约 100 万像素），所以手机上的识别结果可能略有差别。第 0 轮做完后，可以挑几张照片在手机上用 2B 再跑一次对照。

12 张照片 × 2 个模型 = 24 次，每次记一行到 `results.csv`：

```csv
id,model,ocr_ok,figure_ok,whats_wrong,check_panel,answer_ok,seconds,note
p01,2B,对,部分,交点画在了 (1,0)、(-3,0),2/2,是,6+14,核对说全部满足但交点错了
```

- `ocr_ok`：识别出来的题目对不对。**对** / **小错**（有错字但不影响题意）/ **错**（数字、符号或条件错了，题意变了）。
- `figure_ok`：**对**（要点全部满足）/ **部分**（主要图形对，某个要点缺或错）/ **错**（关键图形错）。按你在步骤 2 写的标准判断，不按“核对题目条件”的结果判断。
- `check_panel`：图下方“核对题目条件”显示的结果，例如 `5/5`、`3/5`；没有显示就写 `无`。
- `seconds`：进度条上“识别题目”的秒数 + “分析题意并作图”和“核对题目条件”的秒数，写成 `6+14` 这样。

跑完按类型统计，写进 `../README.md`。**这就是你的第一份评测结果。**

## 步骤 4：挑 3 个失败，写下猜测（约 20 分钟）

在 `notes.md` 里，每个失败写：照片编号、你期望的图、实际画出来的样子，以及**你觉得为什么失败**。先看 `ocr_ok`：识别错了，图多半也会错；识别对了还画错，才是作图的问题。例如：

- 「p03 是识别错了：把 x² 认成了 x2，后面的图自然不对。」
- 「p07 识别是对的，但 2B 自己算错了交点，可能是因为它在心算，而不是让程序去算。」

## 步骤 5：不改代码，先验证猜测（约 20 分钟）

每次只改一个地方，其他都不变：

- 怀疑是**识别错导致画错** → 点题目右上角的「修改」，只把识别错的地方改对，点「重新分析」。这一步只换掉了识别结果，作图部分完全一样，如果这样就画对了，说明问题出在识别上
- 怀疑是**照片不清楚** → 同一道题重拍一张更清楚的再试
- 怀疑是**某条作图命令写错** → 打开「作图命令」，只改那一行，点「重新绘制」
- 怀疑**只是运气不好** → 同一张照片再跑两次，看结果是否一样

如果只改了这一处就对了，猜测就得到了支持。**这已经是一次对照实验了。**

## 步骤 6：做一个小改进，再测一次（30～60 分钟）

根据步骤 5 的发现，选一个最简单的改进（比如在提示词里加一条规则，或者让程序自动做某件事），告诉 Claude 改什么。改完**用同样的 12 张照片再跑一遍**（至少跑 2B），在 `results.csv` 里 `model` 写成 `2B+改进`，对比前后。

## 检查问题：能用自己的话回答，才进入第 1 轮

1. 为什么要**在运行之前**写好“正确的图应该显示什么”？
2. 2B 和 4B 的差别，主要在识别还是在作图？在哪类题上？为什么会这样？
3. 你的改进对哪类题有效，对哪类没用？
4. 只有 12 张照片，能证明什么，不能证明什么？
5. 步骤 5 里「把识别结果改对再重新分析」，为什么能把识别和作图两个原因分开？
6. 图下方“核对题目条件”说“全部满足”，但你判断图是错的——这说明这个核对能证明什么、不能证明什么？
